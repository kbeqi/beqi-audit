# Beqi Audit

Internal tool for Beqi (Webflow agency): Claude audits client Webflow sites on a schedule through Webflow's hosted MCP server, proposes fixes, and applies the ones a human approves. Portfolio dashboard, per-site findings with lifecycle, live agent activity log.

## Stack

- Next.js 16 (App Router, `src/app`; `(app)` is the signed-in shell, `(public)` holds sign-in and shared reports) on Cloudflare Workers via `@opennextjs/cloudflare`. `worker.ts` wraps the OpenNext handler and adds the cron `scheduled` handler and the Workflow class.
- Cloudflare D1 (SQLite) through Drizzle (`src/db/schema.ts`). Migrations in `drizzle/`, applied with wrangler (`npm run db:migrate:local|remote`).
- Cloudflare Workflows run audits and approved fixes (`src/audit/workflow.ts`, one class, `params.kind` = `audit` | `fix`); the same functions run inline when no Workflow binding exists (local `next dev`). Audit steps: prepare → metrics (PageSpeed) → agent (writes the report text) → structure (report text → `AuditReportSchema`, its own step so a parse failure never re-runs the agent) → ai-visibility (optional, never fails the run) → analyze → finalize. The agent stops itself after 24 minutes with a clear error rather than being killed at the step's 30-minute limit, and the prompt caps the report at 40K characters (longer reports are structured from their JSON block only). A `url_not_allowed` fetch error means the site blocks Claude's fetcher (robots.txt or bot protection); the agent reports `aeo.ai-user-fetchers-blocked` and finishes from Webflow data, and `blockedHosts` is kept with the report text in KV. Analyze merges the agent's findings with the deterministic ones from KV (`runs/<id>/psi-findings`, `ai-findings`) and records `summary.regressions` (score delta and new critical/high findings vs the previous completed run).
- Release assurance: `importSitesForConnection` registers a Webflow `site_publish` webhook per site (`data_webhook_tool` create_webhook) pointing at `/api/webhooks/webflow/<siteId>/<secret>`; the secret lives on `sites.webhook_secret`. A publish starts a run with trigger `publish` unless `audit_on_publish` is off, a run is live, or the site ran in the last 10 minutes; outcomes are `run.publish_triggered` / `run.publish_skipped` in `audit_log`. The run page and results email call it a post-publish check and lead with the regressions. Webhooks are skipped when `APP_URL` is localhost; saving site settings with the option on registers a missing one.
- Workers KV (`AUDIT_STORE`) holds per-run artifacts: the structured report, the report text and the full agent transcript under `runs/<runId>/*.json` (90-day TTL). D1 holds findings, scores, proposals, lifecycle and the activity log (`run_events`).
- Auth (`src/lib/auth.ts`): `AUTH_MODE=app` (default) is in-app sign-in by one-time email link (`/login` → `requestSignIn` → `/api/auth/callback`), 30-day session cookie `beqi_session` backed by the `sessions` table (revocable). Only `users` rows (Team page, admins only) and `ADMIN_EMAILS` can sign in; configured admins are auto-created and can't be demoted or removed. Every page calls `requireSignedIn()` (`src/app/gate.tsx`); actions call `currentActor()` / `requireAdmin()`. `AUTH_MODE=access` trusts Cloudflare Access's header instead (must still be a team member); `open` is bring-up only.
- Next.js 16 differs from older versions: read `node_modules/next/dist/docs/` before using an API you are unsure about. `cacheComponents` is off on purpose; pages are `force-dynamic`.

## The engine (`src/agent`)

- Models (`anthropic.ts`): `AUDIT_MODEL` = `claude-opus-5-5` for the audit, structuring and the AI sample; `FIX_MODEL` = `claude-fable-5-1` for the fix agent only (short conversations that write to a client's site; the stronger model costs cents there). `addUsage` prices each call by the model that answered, so mixed-model and fallback runs are costed right. Fable needs standard (30-day) data retention on the Anthropic account.
- `audit.ts`: one streamed `claude-opus-5-5` conversation (adaptive thinking, effort high, server-side fallbacks) with Webflow's MCP server attached through the Anthropic MCP connector (`mcp_servers` + `mcp_toolset`, beta `mcp-client-2026-09-15`) and `web_fetch` scoped to the site's host. Content blocks are mirrored into `run_events` as they complete. A second, tool-free `messages.parse` call turns the written report into `AuditReportSchema` (zod).
- `catalog.ts`: the fixed list of check ids the agent may report (`<category>.<kebab-name>`), their default severity and the fix action each supports. The zod schema enumerates these ids, so the model cannot invent checks. Checks marked `deterministic` (perf.* vitals, ai.*) are produced by code, never by the agent, and are excluded from the agent's schema and catalog text. A finding's identity across runs is `fingerprint` = sha256(checkId | pagePath | subject); renaming an id resets lifecycle state. The catalog states 2026 facts (Google ignores llms.txt, FAQ rich results are gone, AI crawlers split into search / user-fetch / training) and the system prompt forbids recommending llms.txt or FAQ schema as levers.
- Every finding and proposal carries `confidence` (high / medium / low: verified in a tool result, strongly indicated, inferred) and `effort` (quick / moderate / large). The UI shows "quick win" and "likely" / "unverified" pills; the client Fixes tab sorts quick wins first.
- `src/audit/psi.ts`: Core Web Vitals for the key pages (≤5) from Google PageSpeed Insights, mobile, field data (CrUX p75) preferred over lab. Rows go to `page_metrics`, deterministic perf.* findings into the run, and a short text summary into the agent's task prompt so it does not estimate vitals itself. `PSI_API_KEY` is optional.
- `src/agent/ai-visibility.ts`: the AI visibility sample. The audit report names the brand, its aliases, 5–10 key facts and 6–10 customer questions (`sites.ai_prompts` overrides). Each question is asked twice of each engine (Perplexity Sonar when `PERPLEXITY_API_KEY` is set; Claude with `web_search` always), answers are checked for brand mentions and citations of the site's host, then one `messages.parse` call judges recommendations and claims that contradict the key facts. Rows go to `ai_answers`; the summary into `runs.summary.aiVisibility`; deterministic ai.* findings (not-mentioned under 50%, not-cited, one inaccurate-claim per distinct claim). The `ai` category is reported but has weight 0 in the overall score (`SCORED_CATEGORIES`), and the UI always says "sampled".
- `webflow-mcp.ts`: the tool allow-list handed to the connector, and the read/write classifier. Webflow's tools are coarse (`data_pages_tool` with an `action`), so the audit run is also checked after the fact: any write action fails the run.
- `fix.ts`: applies one approved `fix_proposals` row; reads the current value first, skips if it drifted from the proposal's `from`, writes, reads back, returns `FixResultSchema`.
- `prompts.ts`: static system prompts (cached) + per-task user prompts. Site-specific data never goes in the system prompt.

## Conventions

- Nothing writes to a client's Webflow site except the fix agent, only for a `fix_proposals` row with status `approved`, and every outcome is logged in `audit_log`.
- Severity scale: critical / high / medium / low / info. Scores are per category (`src/audit/score.ts`), weighted into an overall 0–100, computed deterministically from the findings.
- Keep Workflow step return values small; persist large data to KV (`AUDIT_STORE`) inside the step.
- D1 limits bound parameters per statement: insert findings in chunks (see `stepAnalyze`).
- Webflow MCP auth (`src/lib/webflow/mcp-oauth.ts`): OAuth against the MCP server using the MCP SDK's `auth()` helper (discovery, dynamic client registration, PKCE, refresh). No Webflow Marketplace app. The registered client is cached in KV; tokens live on `webflow_connections`. `ensureFreshConnection` refreshes a token with under 45 minutes left (an agent step may run 30), after re-reading the row so two runs on one connection don't both rotate the refresh token.
- UI: tokens in `src/app/globals.css` (light and dark are both chosen values; `--*-text` variants are the contrast-safe colours for text, the bare tokens are for fills), components in `src/components/ui.tsx`. Status colors only mean good/warning/serious/critical and always come with a text label.
- Navigation model: Portfolio → Clients → one client's hub (`/clients/[id]` with Overview / Audits / Fixes / Sites / Settings tabs, shared `layout.tsx` header with logo-or-name and Audit now) → site, run and fix pages, whose breadcrumbs lead back into the hub. `/runs` and `/fixes` are cross-client views reachable from the portfolio only.

## Commands

- `npm run dev` — Next dev server with local Cloudflare bindings (D1/KV via Miniflare; audits run inline).
- `npm run preview` — OpenNext build + `wrangler dev` on :8787 (closest to production: Workflows and cron work here; trigger cron with `curl "http://localhost:8787/cdn-cgi/handler/scheduled?cron=0+*+*+*+*"`).
- `npm run deploy` — build and deploy. Run `npm run db:migrate:remote` first when `drizzle/` changed.
- `npm run typecheck`, `npm run lint`, `npm run cf-typegen` (after editing `wrangler.jsonc`).
- `npm run db:generate` after changing `src/db/schema.ts`, then `npm run db:migrate:local`.
- `node scripts/ux-check.mjs [baseUrl] [loginToken]` — orientation (one h1, page titles, breadcrumbs, active nav/tab), labels, axe serious/critical, no horizontal overflow, at desktop and phone widths. Seed a `login_tokens` row and pass its raw token.
- `npm run test:links [baseUrl]` — (set `LINKCHECK_COOKIE=beqi_session=<token>` when sign-in is enforced) crawls the running app (default :8787) and fails on any link that doesn't resolve, hits the error/not-found page, or whose entity label doesn't match the destination heading. Run it against the preview with seed data and against the live URL after a deploy.

## Secrets and vars

Secrets (`wrangler secret put` / `.dev.vars`): `ANTHROPIC_API_KEY`; `RESEND_API_KEY` for sign-in links and client emails (without it every email is recorded as skipped in `audit_log`, and nobody new can sign in); optional `PSI_API_KEY` (PageSpeed quota) and `PERPLEXITY_API_KEY` (adds Perplexity to the AI sample). Vars in `wrangler.jsonc`: `APP_URL`, `WEBFLOW_MCP_URL`, `AUTH_MODE`, `ADMIN_EMAILS`, `EMAIL_FROM`. Declare new secrets in `src/env.d.ts`.

## Shared reports

`shareRun` puts a random token on `runs.share_token`; `/share/<token>` (public layout, `noindex`) renders `src/components/report.tsx` from `sharedReport()`, which exposes no proposals, ids, costs or actions. `unshareRun` clears the token. The brand mark lives in `src/components/brand.tsx` and `src/app/icon.svg` (favicon).

## Client emails (`src/lib/email.ts`)

Per client: `notify_email` (comma-separated), `notify_reminder`, `notify_results`. The scheduler (cron every 20 minutes) first refreshes every active Webflow connection with under 45 minutes left (Webflow's refresh tokens only work while the access token is still valid; an expired one needs a person to reconnect, logged as `webflow.refresh_failed`), then starts due runs, then sends one reminder per upcoming scheduled audit (`sites.reminder_sent_for` guards it, set before sending); `stepFinalize` sends results on a complete run. Sending goes through Resend's HTTP API and never throws; outcomes are `email.sent|skipped|failed` rows in `audit_log`.
